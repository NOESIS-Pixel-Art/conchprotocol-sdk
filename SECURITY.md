# Security policy

> **ConchProtocol Developer Preview is experimental cryptographic software. It has not completed an independent security audit and must not protect production communications.**

## Reporting a vulnerability

Report suspected vulnerabilities privately to
**security@conchprotocol.com**. Include the affected package/version, platform,
impact, and the smallest safe reproducer available. Do not include real private
keys, production credentials, access tokens, personal data, or production
plaintext.

Please allow the security team time to acknowledge, investigate, coordinate a
fix, and notify affected integrators before public disclosure. The final public
coordinated-disclosure and response-time policy remains a release gate; this
scaffold does not promise a specific response or remediation deadline.

Security reports are not customer-support requests. Integration questions go
to **support@conchprotocol.com** and legal/licensing questions to
**legal@conchprotocol.com**.

## Supported versions

There are no publicly supported versions yet. `0.5.0-internal.*` packages are
private artifacts and are not public releases. A support table will be added
only when the exact public package bytes are approved and published.

## Current assurance boundary

No independent security audit, certification, formal verification, production
anchor approval, universal platform coverage, complete memory erasure,
side-channel resistance, exactly-once delivery, or hostile-OS protection is
claimed. Checksums detect changes relative to a trusted record; they are not by
themselves proof of publisher identity.
